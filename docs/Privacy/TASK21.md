# Task 21: face/person detection and exclusion

## Behavior and contract
Uses the existing §5.5 Anonymizer interface and §4.6 vision_faces_people v1 method. The default PipelineOptions anonymizer is now VisionAnonymizer. It runs face, full-person and upper-person rectangle requests on the upright sRGB working copy using orientation .up. Vision's bottom-left boxes are converted to top-left coordinates, expanded by 10% of box width/height on each side, clipped, and stored as normalized padded boxes. Both full- and upper-body requests are required when detect_people is true; failure of any requested detection fails the entire privacy step without partial results.

No arbitrary confidence cutoff is added. Overlapping regions remain recorded but their union is counted once. Bounding boxes, not silhouettes, are excluded, so nearby background can also be excluded. The image blur is a separable box blur, radius 24 working-copy pixels, applied only inside the union. Eligible pixels remain unchanged. The palette receives the processed image and the eligibility mask; blurred replacement colors never contribute. Masked labels are 255. A fully masked image completes privacy and fails the palette with no_eligible_pixels.

Contract parameters are unchanged: detect_faces=true, detect_people=true, box_padding=0.10, blur_radius_px=24. Finite padding in 0...1, radius in 1...256 and at least one requested detector are accepted. Pixel effects and validation use the same padded rectangles and floor/ceil bounds as the existing mask implementation.

## Failure / opt-out
If Vision is unavailable on the platform or required perform calls fail, the step fails with detection_unavailable. Invalid settings, image creation or masking/validation failures use anonymization_failed. Failure retains no partial privacy result. Per §3.4, palette analysis STILL runs on all unmasked working-copy pixels; per D2 no photo/mask/label files are persisted after privacy failure. The result screen prominently explains that failure, that no photo copy was saved, and that colors include unmasked pixels. Cancellation is rethrown; normal privacy failures become recorded steps.

NoOpAnonymizer remains an explicit development/CLI opt-out: skipped/not_implemented with people_not_masked. The contract permits storage for this opt-out. It is not used by default. Do not describe an explicit opt-out as anonymized. The existing CLI owner must map --no-anonymize to this implementation in the current analyze command.

No detections means completed with an empty region list and zero share, NOT proof that nobody is present. The detector conservatively sets may_be_incomplete=true for all successful runs because rectangle detection can miss people. The existing contract template limitation.anonymization_incomplete says detection may miss people, with an explicit no-detection sentence for empty output. No new reason codes, template IDs or root JSON fields are added. Template IDs remain fN and privacy wording is generated only in Findings. Existing Task 11 color sentences are preserved; the privacy limitation explains that shares refer to remaining eligible pixels.

## Storage and original lifecycle
The app passes original bytes to ImageLoader as required. The image/bytes needed to detect and process exist transiently in memory. Submitting analysis clears the view's original preview and picker state; errors/cancellation also clear those references. Active task input remains alive until the task unwinds. This is reference release, NOT a forensic secure-zeroization guarantee for Swift Data, image buffers or OS caches.

Only the processed working copy is returned as storedImage for successful default detection. FileAssessmentStore continues its existing atomic JSON/PNG writes and no-recompute reopen. StoreRules rejects a nonnil stored image after privacy failure and checks completed privacy masks, dimensions and excluded labels before either store saves. A normal successful palette save retains assessment.json, image.png, mask.png, labels.png as §6 requires. If palette fails there is no labels.png. Privacy failure saves JSON only. Source photos in Photos and source dataset files are NOT deleted; CLI source.original.retained may stay true per §4.3. Existing pre-Task21 assessments are not retroactively anonymized; delete old non-anonymized test assessments if they should not remain on the test device.

## JSON and cross-consumer validation
AssessmentSteps.anonymization is now StepRecord<AnonymizationResult> instead of opaque ContractJSON. The existing schema v1 field shape is unchanged; older null/skipped/failed results still decode. AssessmentValidator and the strict wire checker now support the exact §4.6 result and closed keys, valid regions, rectangle-union share, mask/eligible counts, required limitations, and failed-step no-image rules. Unknown keys are rejected. No completed quality or contrast support is added in this task.

The supplied anonymization-step.schema.json is a standalone validation fragment, not a replacement root schema. The repo's full JSON Schema and docs/assessment/validate_assessments.py were not supplied: their owner must integrate this step shape and semantic checks before merge, using the shared complete/partial fixtures. In particular check masked_share iff nonempty regions, normalized rect sums, rectangle-union share and limitation/dependency rules. Public or external call sites that construct completed privacy as ContractJSON must switch to AnonymizationResult. Do not change the source schema version for implementation of an already specified v1 result.

## Test coverage
AnonymizationTests uses deterministic injected detections, never claims to verify real face/person recall. It covers defaults; coordinate flip/padding/clipping; invalid coordinates; union counts; blur/unchanged eligible pixels; empty detections; masked red excluded from blue-only palette; fully masked input; unavailable/error/cancel paths; closed JSON and round trip; bad shares; stored processed artifact/relaunch equality in both stores; photo-after-failure rejection; and explicit opt-out. An opt-in live Vision smoke test exists, but tiny synthetic input is not a detector-accuracy test. AssessmentStoreTests explicitly uses NoOp because it tests storage, independently of OS Vision availability. Existing pipeline tests that assumed default skipped privacy must similarly inject NoOp, while app/default tests must expect Vision.

## Review and device checks
Run the supplied deterministic tests and all existing tests. Run live Vision on macOS and iOS separately. Use consented/licensed test photos with a frontal face, profile face, full person, cropped person, multiple/overlapping people, edge-of-image person, no people and EXIF-rotated copies. Verify stored padded boxes align with the upright photo, marked pixels are blurred and ineligible, zero detections still carries the limitation, and person/face detection failures do not persist an image. Inspect actual saved files, masks and labels after relaunch. Test cancel before/during analysis and save; verify the existing Task14 cancel cleanup leaves no unexpected assessment. Test on two physical iPhones and have another teammate inspect the masked images. Blurring/detection is best effort and does not guarantee anonymity.

Known existing dependencies: CStbImage/PNGCodec, current orientation/color loader, Task14 backup/file-protection policy and store concurrency are retained, not replaced. The contract's Apple-only-code cleanup is a separate existing integration issue; no new third-party dependency is introduced here.
